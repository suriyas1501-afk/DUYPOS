# POS System (ระบบขายหน้าร้าน)

Thai-language, offline-first POS web app (PWA). All UI text is Thai. MVP scope: single branch. Future phases: Electron wrap, multi-branch sync, ERP.

## Commands
- `npm run dev` — dev server on port 5173 (or use `.claude/launch.json` → `pos-dev`)
- `npm run build` — typecheck (`tsc -b`) + production build
- `node scripts/gen-icons.mjs` — regenerate PWA PNGs from `public/icon.svg`

## Stack
Vite + React 19 + TypeScript strict (`verbatimModuleSyntax` — always `import type`) + Tailwind v4 (emerald primary, cards `bg-white rounded-2xl`) + Dexie (IndexedDB `pos-db`) + Zustand + Recharts. Font: Noto Sans Thai (bundled).

## Architecture
- **All data lives in IndexedDB** via `src/db/db.ts` (tables: products, categories, members, promotions, sales, stockMoves, heldBills, settings, expenses, coupons, goodsReceipts, stockCounts, staff, shifts, taxInvoices — v2 added `expenses`, v3 added coupons/receipts/counts, v4 added staff/shifts/taxInvoices; bump schema with additive `this.version(n)` calls only). `settings` is a single row `id=1`; read it with `useSettings()` from `src/db/hooks.ts`. Reactive reads via `useLiveQuery` (dexie-react-hooks).
- **Money/promo engine** in `src/lib/`: `promotions.ts` (auto-promo engine; bill-level promos pick the single best), `coupons.ts` (code validation + discount), `totals.ts` (`computeTotals` — discount order: line manual → line promo → bill promo → **coupon** → bill manual → points), `checkout.ts` (`finalizeSale`/`voidSale`/`refundSale` — Dexie transactions that also move stock, member points, coupon usage).
- **Refunds are negative-amount documents**: a partial refund creates a `Sale` with `kind: 'refund'` whose `total`/`vatAmount`/`items[].qty`/`items[].total` are all negative, so every Σ aggregation nets automatically. Consequence: any **bill count** must filter `kind !== 'refund'`, and charts must drop non-positive aggregates. Originals track `refundedTotal` + per-item `refundedQty`.
- **Split tender**: `Sale.payments: Payment[]`; always split per-channel amounts with `saleAmountByMethod()` (handles change-from-cash, legacy bills without `payments[]`, and negative refund payments) — never compare `sale.paymentMethod` directly.
- **Multi-unit products**: `Product.units[]` (name/barcode/factor/price). Stock always moves in base units (`qty × unitFactor`); `SaleItem.cost` is per sold unit. `allowDecimalQty` enables weighed sales; `wholesalePrice`/`wholesaleMinQty` swap in via `effectivePrice()` in the cart whenever qty changes.
- Document numbers come from `src/lib/docNo.ts` (`nextSeq` takes the max existing suffix of that day, not a row count — survives restore/void). Prefixes: `R` sale, `RF` refund, `GR` goods receipt, `SC` stock count, `SH` shift, `TX` tax invoice, `CN` credit note.
- **Staff & permissions** (`Settings.staffEnabled` opt-in): `Staff` rows hold a hashed PIN (`src/lib/auth.ts`, `'sha256$<salt>$<hex>'`, never the PIN). Hashing **must not** depend on `crypto.subtle` alone — it's absent outside secure contexts (a POS opened over `http://<LAN-ip>`), so `auth.ts` ships a pure-JS SHA-256 and both paths must produce identical digests. `src/lib/permissions.ts` owns `PermissionKey`, role defaults (`ROLE_PERMS`) and `hasPerm()`; per-staff `perms` only stores **deviations** from the role. Gate UI with `usePermissions().can(perm)` (returns `true` for everything when `staffEnabled` is off) **and re-check at the write site** — hiding a button is not a permission (see `StockModal`/`ImportCsvModal`/`ProductModal` initial stock, all of which need `stock`, not `products`). Routes use `<RequirePerm>`; a manager can authorize an action a cashier lacks via `PinApprovalModal`.
- **Login state** (`src/stores/authStore.ts`) persists `staffId` + `locked` only; the `Staff` row is read live via `useCurrentStaff()`. That hook's `useLiveQuery` result **carries the staffId it was computed for** — Dexie keeps serving the *previous* result for a frame after deps change, and trusting it logs the user straight back out on login. Locking renders `LockOverlay` **on top of** the still-mounted app (so the cart and current page survive), which means every `window` keydown listener must bail when `useAuth.getState().locked`.
- **`src/lib/actor.ts`** is how non-React code learns who is acting: `App.tsx` calls `setActor()` on staff change, and `finalizeSale`/`refundSale`/shift/goods-receipt/stock-count/expense writes stamp `staffId`+`staffName` from `getActor()`. Pass an explicit `actor` argument instead when someone **else** approved the action (e.g. manager-approved void).
- **Shifts** (`Settings.shiftEnabled`): one `status:'open'` row at a time. `finalizeSale`/`refundSale` stamp `Sale.shiftId`; expenses stamp `shiftId` too. **All cash math lives in `computeShiftSummary()` (`src/lib/shift.ts`)** — expected cash = opening + cash sales (via `saleAmountByMethod`, already net of change and refunds) − cash expenses + cash-in − cash-out; never re-derive it in a component. `closeShift()` recomputes the summary from the DB rather than trusting the screen. `requireShiftToSell` is enforced inside `finalizeSale`/`refundSale`, not just in the UI.
- **Cash must never leave the drawer untracked.** `voidSale` refuses a bill belonging to an already-closed shift (use a refund instead, which lands in the open shift), and `openShift()` adopts bills/expenses created in the gap since the last shift closed so their cash isn't a mystery surplus. The daily-close figure (`cashNet`, whole day, *excludes* opening float) and the shift figure (`expectedCash`, per shift, *includes* it) differ on purpose — both must account for `cashMoves`.
- **Full tax invoices** (`Settings.vatRegistered`): `src/lib/taxInvoice.ts` issues one active `TaxInvoice` per bill (`Sale.taxInvoiceId`), refund docs become `kind:'creditNote'` and **require** the original bill's invoice first. Amounts are stored **positive** with direction carried by `kind`; `net = |total| − |vatAmount|` for both VAT-included and VAT-added shops. Cancelling keeps the row (numbers are never reused) and clears the link so a corrected invoice can be issued; `voidSale` refuses a bill that still has an active invoice. Printing is A4 (`src/lib/taxInvoiceDoc.ts`, its own `@page` CSS — not `slipStyle`) with baht text from `src/lib/bahtText.ts`.
- **Receipts** print via `#print-area` div in `index.html` (`src/lib/receipt.ts` builds HTML string, `@media print` CSS in `src/index.css` hides `#root`). Widths 58/80mm from settings. Every document builder must escape user text with the shared `esc()` and render the shop logo with `logoImg()` from `receipt.ts` (escapes quotes and accepts only `data:image/` — a logo lands inside `src="…"`).
- **Cart** is Zustand (`src/stores/cartStore.ts`), keyed by product+options+note+price for line merging. `productId 0` = ad-hoc custom item (skips stock/promos). It persists to localStorage and gets copied into `heldBills`, so anything that authorizes a cart value must live **in the cart too** — `discountApprovedById/Name` rides along with the discount and is stamped onto the `Sale`; a cart carrying a discount with no approver is cleared when the current user lacks `discount`.
- Shared UI kit: `src/components/ui.tsx` (Button, Modal, Icon, toast, …) — use it, don't hand-roll.
- Business mode `retail` | `cafe` (settings) tweaks POS grid density; product options work in both.

## Conventions
- Round money with `r2()` at aggregation points; format with `baht()`/`money()` from `src/lib/format.ts`. Dates via Intl `th-TH` (Buddhist era is expected).
- Seed/sample data in `src/db/seed.ts` — auto-increment ids, seeds **only tables that are empty** (never overwrite a real shop's data) and returns `{added, skipped}`. `initDb()` runs on app start, requests `navigator.storage.persist()`, calls `ensureOwnerStaff()` (owner `E01`, PIN `1234`, so enabling staff mode can never lock you out), and is idempotent.
- Never let a user strand themselves outside the app: `clearAllData(keepSettings)` keeps the `staff` table, and `LoginScreen` offers "recreate owner" / "turn staff mode off" when no active staff remains.
- **Backups are the only recovery path** (everything lives in one browser's IndexedDB). `src/lib/backup.ts` writes a daily file into a user-picked folder via the File System Access API — the handle lives in the `appState` table, which is deliberately **outside `TABLES`** so it never lands in a backup file or gets wiped by `clearAllData`. Picking a folder and re-granting permission need a user gesture, so startup only ever calls `ensureFolderPermission(handle, false)`; the overdue banner in `Layout` is what turns a click into a permission prompt. Browsers without the API still get the reminder + download path.
- The cart (`cartStore`) persists to localStorage under `pos-cart`, so a mid-bill refresh doesn't lose the basket. Every route is wrapped in `ErrorBoundary` — a render crash shows a recovery card, not a white screen.
